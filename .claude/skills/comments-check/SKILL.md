# 注释检查（青禾记账）

按项目注释规范审查代码注释。依据：CLAUDE.md「黄金规则 · CODE COMMENTS」。

## 合规标准

**禁止**（建议删除或改写）：
- 复述代码（把代码翻译成一句话）
- 叙述控制流（`// 先排序再求和`）
- 标签化普通变量/函数（`// count 表示计数`）
- 解释语法（`// ?? 是空值合并运算符`）
- **过期/失真注释**（代码已改、注释未改 → 最有害，它在骗人）
- 注释掉的代码块（dead code，git 历史可找回）
- 空注释 / 明显废话

**允许**（保留）：
- 非显然的意图、约束、绕过方案、外部怪癖、回归背景
- 棘手的迁移/幂等/兼容性说明
- 格式/列位约定（如 CSV 列位序、参数上限）
- 单句为佳，最多 2-3 句

**本仓库既有惯例**（允许，但别新增过密）：文件头 `// 青禾记账 - xxx`、分区横幅 `// ============ 花销操作 ============`。

## 合法注释范例（对照可引）

- `src/db.ts` — `// 迁移：已有库补 type 列（新建库的 CREATE 已含，此步幂等）`：幂等迁移的非显然意图。
- `src/db.ts` — `// 首次使用时导入默认分类（只数支出分类：收入预设先入库，全表计数恒非 0，新库会漏种支出分类）`：回归背景 + 坑位。
- `src/csv.ts` — `// 7 列格式…类型放末列 → 旧 6 列文件的字段位序完全不变，导入兼容`：兼容性约束。

## 流程

1. 定范围：用户指定 diff/文件/目录；未指定则全量 `src/**`。
2. grep 注释：`^\s*//`、`/* … */`、多行 `*` 行、行尾 `//`。
3. 对每条注释分类（禁止 / 允许 / 惯例）。
4. 过期检查：逐条把注释内容对照下方实现验证是否仍成立——**先查"说的还是不是真的"**，这比"该不该有"更重要。
5. 只报告不改；仅当用户同一请求里要求修复时才动手。

## 输出格式

- 违规清单：`file:line` + 注释原文 + 违规类型 + 建议动作（删/改/精简/恢复）。
- **过期/失真注释单独一组**，明显最高优先级。
- 末尾：保留的价值注释（可选）+ 统计（共 N 条注释 / M 条违规 / K 条过期）。
